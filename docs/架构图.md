## 完整游戏流程标杆（待定义）

完整游戏的局外入口、菜谱选择、关卡或存档规则尚未确定。当前仓库只有直接进入 `SampleScene` 的料理演示，所以下图是**已实现的 Demo 流程**，不是完整游戏承诺。未来确定完整业务流程后，在本节补充正式流程；若流程发生大改，同一提交追加架构版本。

### 当前 Demo 玩家流程

```mermaid
flowchart TD
    START[运行 SampleScene] --> LOAD[读取 DemoRecipe 并构造运行时菜谱]
    LOAD --> VALID{配置有效?}
    VALID -->|否| ERROR[记录错误并停用输入控制器]
    VALID -->|是| ROUND[开始当前轮次与第一项工序]
    ROUND --> INPUT[玩家左右换位，按下或松开 J]
    INPUT --> CHECK{站位与输入符合当前工序?}
    CHECK -->|否| INPUT
    CHECK -->|是| PROGRESS[累积短按、连续按或长按进度]
    PROGRESS --> DONE{当前工序完成?}
    DONE -->|否| INPUT
    DONE -->|是，尚有工序| NEXT_OP[立即激活下一工序]
    NEXT_OP --> INPUT
    DONE -->|是，本轮结束| GRADE[按本轮耗时评价并累计菜谱进度]
    INPUT -->|超过 Good 时限| MISS[本轮评价 Miss]
    MISS --> GRADE
    GRADE --> RESULT[短暂展示本轮结果]
    RESULT --> SUCCESS{菜谱进度达到 100%?}
    SUCCESS -->|是| WIN[显示完成]
    SUCCESS -->|否| MORE{还有固定轮次?}
    MORE -->|是| ROUND
    MORE -->|否| LOSE[显示失败]
```

## 目标架构基线（待定义）

当前尚无经确认的完整游戏目标架构。现阶段只固定已经实现的边界：料理规则由纯 C# 核心拥有；Unity 配置负责把资源转成运行时数据；输入、场景对象、Animator 和 HUD 留在 Unity 适配与表现层。菜单、跨场景服务、存档和 Autoload 均**未实现，也未定义目标方案**。后续确定这些能力时，先明确生命周期与数据所有权，再追加新版本快照。

## V1：固定菜谱料理 Demo（2026-10-04）

对应代码基线：`efe3c5d`。料理功能目前是单场景、一道演示菜谱、六种工序、三轮固定顺序。料理运行时代码位于 `Cook.Runtime`；`Core` 是该程序集内不引用 Unity 的代码目录，尚未拆为独立程序集。

### 目录与职责

| 位置 | 当前职责 |
|---|---|
| `Assets/Scripts/Cooking/Core` | `CookingSession` 持有状态、工序进度、轮次计时、评价与菜谱进度；`CookingTypes` 定义运行时数据和枚举。 |
| `Assets/Scripts/Cooking/Configuration` | `OperationDefinition`、`RecipeDefinition` 保存 ScriptableObject 配置，校验并转换成核心运行时数据。 |
| `Assets/Scripts/Input`、`Assets/Scripts/CookingInputController.cs` | Input Actions 与 MonoBehaviour 生命周期适配，把输入和 `deltaTime` 转交给核心，并在结果展示后推进轮次。 |
| `Assets/Scripts/Cooking/Presentation` | `CookingAnimationPresenter` 消费站位与工序事件；`CookingHud` 消费进度与结果事件。两者不决定玩法状态。 |
| `Assets/Cooking` | 六种工序资源与 `DemoRecipe` 固定轮次资源。 |
| `Assets/Animations`、`Assets/Fonts`、`Assets/Scenes` | 占位动画与 Animator Controller、TMP 字体、唯一可玩的 `SampleScene`。 |
| `Assets/Editor/CookingDemoBuilder.cs` | 编辑器侧生成演示配置、动画 Controller 与场景绑定；不参与运行时流程。 |
| `Assets/Tests` | EditMode 规则与资源测试、PlayMode 表现测试。 |

### 模块边界与数据流

```mermaid
flowchart LR
    subgraph Editor[编辑器与资源]
        BUILDER[CookingDemoBuilder]
        ASSETS[OperationDefinition / RecipeDefinition]
        SCENE[SampleScene / Animator Controller / TMP 字体]
        BUILDER --> ASSETS
        BUILDER --> SCENE
    end

    subgraph Runtime[Cook.Runtime]
        INPUT[CookInputActions]
        ADAPTER[CookingInputController]
        CONFIG[RecipeDefinition.TryBuildRuntime]
        CORE[CookingSession + RuntimeData]
        ANIM[CookingAnimationPresenter]
        HUD[CookingHud]
    end

    ASSETS --> CONFIG
    SCENE --> ADAPTER
    INPUT -->|左右换位 / J 按下松开| ADAPTER
    ADAPTER -->|创建会话、输入、Tick、推进结果| CORE
    CONFIG -->|只读运行时菜谱| CORE
    CORE -->|站位 / 工序事件| ANIM
    CORE -->|进度 / 评价 / 终局事件| HUD
    ANIM -->|启用站位角色、Animator Trigger| SCENE
    HUD -->|TMP 文本、Image 进度| SCENE
```

配置资源不在运行时被核心直接读取。核心不引用 Input System、MonoBehaviour、场景对象、Animator 或 UI；表现层只订阅核心事件，动画播放不反向驱动规则或工序切换。`CookingInputController` 是当前会话的场景级拥有者，退出场景后会话随对象销毁。

### 一次工序的运行流程

```mermaid
sequenceDiagram
    actor Player as 玩家
    participant Input as CookInputActions
    participant Adapter as CookingInputController
    participant Session as CookingSession
    participant Animation as CookingAnimationPresenter
    participant HUD as CookingHud

    Player->>Input: 左右换位或按下、松开 J
    Input->>Adapter: InputAction 回调
    Adapter->>Session: MoveStation / PressCook / ReleaseCook
    Adapter->>Session: Tick(deltaTime)
    Session->>Session: 校验站位、累积进度、判定完成
    Session-->>Animation: StationChanged / OperationStarted / OperationCompleted
    Session-->>HUD: OperationProgressChanged / RecipeProgressChanged / RoundEvaluated
    Animation->>Animation: 切换站位对象并发送 Animator Trigger
    HUD->>HUD: 更新 TMP 文本与 Image 宽度
```

### 状态归属

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> RoundIntro: StartRecipe
    RoundIntro --> OperationActive: 开始本轮第一工序
    OperationActive --> OperationActive: 当前工序完成，下一工序立即激活
    OperationActive --> RoundResult: 全部工序完成或超出 Good 时限
    RoundResult --> RecipeSuccess: 进度达到 100%
    RoundResult --> RoundIntro: 未满 100% 且还有轮次
    RoundResult --> RecipeFailure: 轮次耗尽且未满 100%
```

- `CookingSession` 独占站位、当前轮次和工序、按键保持状态、计时、评价与菜谱进度。
- `CookingInputController` 只负责 Input System 回调、逐帧 `Tick` 和约 0.75 秒的结果展示等待。
- `CookingAnimationPresenter` 只负责三个站位角色的显隐及 Animator Trigger；目标工位未激活时，Trigger 在切换到该工位后发送。
- `CookingHud` 只显示工序顺序、Image 进度、评价与最终结果。

### 场景与生命周期现状

`EditorBuildSettings` 目前只启用 `Assets/Scenes/SampleScene.unity`。场景中的 `CookingGameplay` 持有输入控制器和动画表现组件，`CookingHUD` 持有 HUD；启动时从 `DemoRecipe` 构建运行时菜谱并创建 `CookingSession`。当前没有菜单入口、跨场景持久对象、Autoload、存档读写或结果持久化。成功或失败只显示在当前场景 HUD 中，不会记录到下次启动。
