# 菜单、库存与售卖入口实施方案

## 已确认设计

- 菜单读取 DishCatalogDefinition 的菜品展示配置，确认制作请求直接交给 CookController。
- 制作中可浏览菜单，倒计时继续；确认按钮明确标为取消当前并制作。重新开始只重做当前菜品，保留库存。
- InventoryManager 为 GameManager 持有的普通 C# 类，容量 3；StoredDish 保存独立 ID 与完整 ProductionResult，相同菜品分别存放。同一结果重复提交不重复入库。
- CookController 在完成回调同步入库，成功后广播 InventoryChanged；入库失败保留待入库结果，阻止新制作覆盖它。
- 售卖入口允许选择库存中的 1–3 道，确认后进入售卖准备阶段；不扣除库存，不实现顾客、评级、价格、Buff 或收益。返回制作清空售卖选择，保留库存。
- 没有店铺等级业务时不模拟解锁或升级：菜单展示配置列表，解锁筛选后续接入。
- 库存随 GameManager 跨场景保留，退出游戏丢弃，没有磁盘存档。

## 实施顺序与完成标准

1. 针对性测试：验证容量、同结果防重、相同菜品独立成品；验证完成入库、满库拒绝制作、取消与售卖选择。
2. 库存核心：新增 StoredDish / InventoryManager，入口初始化库存，不依赖 Unity UI。
3. 场景协调：CookController 接菜单、库存和 Production / SaleSelection / SaleReady 阶段；售卖前校验实例 ID 和选择数量。
4. UI：MenuPanel、SalePanel 和 HUD 库存状态；无图标使用 Image 占位。明确取消当前制作按钮，不把选择点击直接当作取消。
5. 编辑器接线：新增独立入口 UI Builder，只添加相关面板和绑定，不改动画或用户布景。修改 Unity 资源前提交代码基线。
6. 追加架构 V11，核查编译与控制台，仅运行新增库存及入口测试，再检查实际 UI 截图。

## 模块边界

可复用：有容量和防重约束的库存规则、已有输入与事件服务。
需适配复用：库存条目采用本项目的制作结果；其他项目替换条目数据即可。
项目专用：CookController 阶段协调、菜单与售卖面板、场景生成接线。SaleReady 仅拥有选定成品的只读快照，不创建尚未设计的 SaleSession。

## 实施结果

- 已完成上述 6 项并接通 GameScene；当前菜单表仅有练习料理。
- 库存 3 项 NUnit 断言在编辑器直接执行通过（测试任务初始化超时后改为直接调用测试方法）。
- MenuInventorySceneTests 的 3 项 PlayMode 测试通过：菜单与防重复开始、满库与售卖选择校验、重启和取消保留库存。
- 通过实际 Button.onClick 验证菜单确认、完成入库、售卖成品选择、确认准备与返回制作；库存未扣除。
- 场景验证无缺失脚本或损坏 Prefab，编译与最终控制台无错误；菜单及售卖准备截图已核查，临时播放设置已恢复。
- 售卖入口完成，顾客服务、实际售出、收益与存档不属于本次实现。
